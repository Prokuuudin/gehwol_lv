# gehwol.lv

Сайт-визитка и каталог GEHWOL в Латвии (Versija Intersource, SIA). Без интернет-магазина, регистрации и форм. Товары, новости и статьи редактируются в PHP-админке и появляются на сайте сразу — без сборки и без разработчика.

## Как устроено

```
src/ (HTML-блоки, SCSS, JS, img)  --gulp-->  docs/           статика: css, js, img, шрифты, юридические страницы, robots.txt, .htaccess
                                         └->  php/templates/  главная, страницы категорий, общая оболочка (с местами <x-slot> для данных)

php/data/*.json  (товары, новости, статьи, категории)  <-- php/admin/  (админка)
        │
        └-->  php/site.php  -->  страницы товаров, категорий, новостей, статей, главная, sitemap.xml, 404
```

- Адреса страниц: `produkts-N.html`, `jaunums-N.html`, `raksts-N.html`, `<категория>.html`, `index.html`. Запрос, для которого нет готового файла, `.htaccess` передаёт в `php/site.php`.
- Данные — JSON-файлы в `php/data/` (база данных не нужна). Запись атомарная, прежняя версия каждый раз сохраняется в `php/data/backups/` (20 последних).
- Тексты хранятся как HTML с ограниченным набором тегов; в админке простой текст («пустая строка — новый абзац») превращается в абзацы.
- Категории фиксированы (21 шт., меню и страницы категорий — часть шаблонов): в админке только список. Новая категория или переименование — задача разработчика (`php/data/categories.json`, страница в `src/html/`, пункт меню в `src/html/blocks/header.html` и `mobile-nav.html`).
- Загруженные изображения проверяются, уменьшаются до 1600 px, очищаются от EXIF и получают WebP-копию (`uploads/`). Изображения каталога лежат в `src/img/` и обрабатываются gulp.

## Требования

- Разработка: Node.js (gulp), PHP 8.1+ с Composer. Локально GD/exif можно не включать в php.ini — `composer test` подключает их сам.
- Сервер: PHP 8.1+ (GD с WebP желательно), Apache с `.htaccess`. Подробности — [DEPLOY.md](DEPLOY.md).

## Команды

```
npm install && composer install     # один раз

npm run build:quick   # HTML-шаблоны, SEO, CSS (секунды) — после правок в src/html или src/scss
npm run build         # полная сборка docs/ с изображениями и шрифтами (минуты); завершается сама
npm run preview       # локальный сайт + админка: http://127.0.0.1:8010/ и /php/admin/
composer test         # PHP-тесты
npm run check         # SEO, sitemap, robots, внутренние ссылки и отсутствующие файлы по всем страницам
npm run release       # папка release/ для выкладки (без данных)
```

`docs/` и `php/templates/` — результат сборки, они хранятся в git: сервер и CI используют их без запуска gulp. После правок в `src/` пересоберите и закоммитьте.

Для `npm run preview` нужен локальный администратор: `php php/bin/set-password.php <логин>` (файл `php/data/admin_users.json` в git не попадает).

## Админка

- Адрес: `/php/admin/`. Первый администратор или сброс пароля: `php php/bin/set-password.php <логин>`.
- Пароль: от 10 символов, буквы и цифры; сменить — страница «Parole». После 5 неверных паролей вход с IP блокируется на 15 минут; после 30 минут бездействия нужно войти снова.
- «Priekšskatīt» в форме редактирования показывает материал, как на сайте, в том числе черновик (только для вошедших).
- Флажок «Publicēts» снимает материал с сайта без удаления (черновик отвечает 404 и не попадает в sitemap). Удаление требует подтверждения; после него запись и связанные изображения можно восстановить кнопкой «Atcelt dzēšanu» в течение 5 минут. ID удалённых записей повторно не используются.
- «Servera pārbaude» (`health.php`) — версия PHP, расширения, права записи, данные, версия выкладки.
- Вход, выход и изменения записываются в журнал ошибок PHP сервера с префиксом `[gehwol-admin]` (без паролей и токенов).

## Выкладка, резервные копии, откат

См. [DEPLOY.md](DEPLOY.md): первая установка, обновление без потери данных, резервное копирование `php/data/` и `uploads/`, восстановление (`php php/bin/restore.php`), откат версии, перенос на другой сервер, настройка для nginx.

## Структура

| Путь | Назначение |
|---|---|
| `src/html/` | страницы и блоки (gulp-file-include); `_shell.html` — оболочка страниц из данных |
| `src/scss/`, `src/js/`, `src/img/`, `src/fonts/` | оформление |
| `src/.htaccess`, `src/.user.ini` | настройки сервера (копируются в `docs/`) |
| `src/seo/content.json`, `seo.config.json` | тексты категорий и адрес сайта для SEO |
| `gulp/` | задачи сборки; `templates.js` переносит шаблоны в `php/templates/` |
| `php/site.php`, `php/includes/` | публичные страницы, хранилище, загрузки, авторизация |
| `php/admin/` | админка |
| `php/bin/` | CLI: `set-password.php`, `restore.php`, `render-all.php`, `dev-router.php`, `migrate.php` (разовый перенос данных, выполнен) |
| `php/data/` | данные (JSON) и `backups/` |
| `scripts/` | `check-seo.js`, `build-release.js` |
| `tests/` | PHPUnit |

`SEO.md` — правила SEO. `plans/`, `specs/` и «Заметки по сборке.md» — исторические заметки, к текущей схеме не относятся.
